# Поддерживаемый трафик и управление маршрутом

## Поддерживаемый трафик

### Короткий текст для UI

> OnionRoute MVP поддерживает системный TCP-трафик и DNS внутри защищённого
> маршрута. Неподдерживаемый трафик блокируется без прямого fallback.

### Матрица

| Трафик | Статус MVP | Что увидит пользователь |
|---|---|---|
| IPv4 TCP | Поддерживается в пределах platform coverage и egress policy | Направляется через выбранный маршрут. |
| DNS для protected apps | Поддерживается внутри tunnel | При ошибке возвращается локальный сбой; system DNS не используется. |
| IPv6 | Не является разрешённым egress MVP | Блокируется, пока platform leak tests не подтвердят полноценную поддержку. |
| Произвольный UDP | Не поддерживается | Локально блокируется; direct fallback отсутствует. |
| QUIC / HTTP/3 | Не поддерживается, потому что использует UDP | Блокируется; браузер может самостоятельно повторить запрос по TCP/HTTP/2. |
| WebRTC media/STUN/TURN по UDP | Не поддерживается | Звонок или media может не установиться; direct UDP не разрешается. |
| ICMP и неизвестные IP protocols | Не поддерживаются | Блокируются, а не обходят tunnel. |
| BitTorrent | Запрещён policy | Соединение отклоняется. Классификация TCP не обещается как идеальная. |
| Исходящий SMTP TCP/25 | Запрещён policy | Соединение отклоняется. |
| TCP к private, loopback, link-local, metadata и management ranges через exit | Запрещён | Соединение отклоняется до egress dial. |

«Системный» означает охват, доказанный отдельно для каждой ОС. OS services,
privileged namespaces и platform exclusions MUST быть перечислены в release notes;
нельзя подразумевать 100% охват без leak evidence.

## Почему UDP не поддерживается

### Пользовательский текст

> Текущий flow engine передаёт TCP. Произвольный UDP требует отдельной модели
> маршрутизации, DNS/WebRTC leak controls, backpressure и abuse protection. Пока эти
> механизмы не реализованы и не проверены, UDP блокируется, чтобы приложение не
> отправило его напрямую.

### UX-требования

- Предупреждение MUST отображаться в onboarding, справке и при первой фактической
  блокировке приложения.
- Статус не должен говорить «Internet недоступен», если определённо заблокирован
  только UDP.
- UI SHOULD связывать повторяющиеся события в одно уведомление на приложение и
  protocol class; destination/IP показывать и логировать нельзя.
- Кнопки `Разрешить напрямую` и `Временно отключить защиту` запрещены.
- Если приложение умеет TCP fallback, OnionRoute не обещает и не эмулирует его —
  решение принимает само приложение.

## Выбор страны выхода

### Пользовательский текст

> Страна задаёт расположение private exit gateway для Standard, Enhanced и Maximum.
> OnionRoute выбирает только исправный совместимый exit из подписанного directory.
> Если такого exit нет, приложение не подменяет страну незаметно.

> Страна — свойство управляемого gateway, а не гарантия GeoIP-ответа стороннего
> сайта. Базы геолокации обновляются независимо и могут показывать другую страну.

### Поведение

- `Автоматически` выбирает доступный compatible exit по health/load policy.
- Ручной выбор ограничивает exit выбранной страной.
- Entry/relay могут находиться в других странах; UI не должен представлять выбранную
  страну как местоположение всей цепочки.
- Direct Tor не использует private gateway selection; selector disabled.
- Если выбранная страна недоступна, допустимы только: сохранить старый здоровый
  маршрут, предложить пользователю другую страну/Automatic или блокировать новые
  соединения. Automatic wrong-country fallback запрещён.
- После успешной смены UI показывает фактически активную страну. До этого статус:
  `Изменение не применено — используется предыдущий защищённый маршрут`.

## Автоматическая смена цепочек

### Пользовательский текст

> OnionRoute периодически создаёт новый Tor isolation context и новый gateway
> session. Новые соединения переходят на новый маршрут после его проверки. Уже
> открытые TCP-соединения могут временно оставаться на прежнем маршруте.

Текущие scheduler windows: Standard/Direct Tor — 15–30 минут, Enhanced — 10–20
минут, Maximum — 5–15 минут. UI не обещает точный момент: добавляется jitter,
ротация может быть отложена при недоступности безопасной замены.

### Поведение

- Обычная ротация выполняется make-before-break и не закрывает active TCP.
- Новый route получает fresh isolation и gateway session; после переключения
  очищается связанный DNS cache.
- Если replacement не готов, старый healthy route остаётся active и UI сообщает об
  отсрочке.
- Если потеряны оба пути, трафик блокируется во время reconnect.
- Нельзя говорить «IP изменён», пока новый egress не проверен; даже после ротации
  gateway может иметь тот же внешний IP.

## Новая личность / identity reset

Предпочтительный label: `Сбросить сетевую сессию`. Если используется привычный label
`Новая личность`, рядом MUST быть пояснение `Закроет соединения; cookies и логины не
изменятся`.

### Текст перед подтверждением

**Заголовок:** Сбросить сетевую сессию?

> OnionRoute закроет активные соединения, создаст новый Tor isolation context,
> очистит временный DNS state и получит новую gateway session. Загрузки, звонки и
> другие активные операции прервутся.

> Это не удаляет cookies, логины, local storage или fingerprint приложения и не
> гарантирует новый внешний IP или страну.

Кнопки: `Сбросить сессию` и `Отмена`.

### После успеха

> Сетевая сессия сброшена. Новые соединения используют заново построенный маршрут.
> Идентификаторы сайтов и приложений не изменены.

Hard reset rate-limited. Повторный запрос получает конкретное время ожидания только
если оно вычислено локально; иначе: `Повторите позже`.

## Kill switch

### Пользовательский текст

> Kill switch блокирует трафик, который должен идти через OnionRoute, пока
> защищённый маршрут не готов или потерян. Он включается и независимо проверяется до
> Tor bootstrap. При сбое нет прямого clearnet или system DNS fallback.

### Состояния

- `Включается`: firewall rules ещё проверяются; connect не начат.
- `Активен`: rules проверены и сохраняются при bootstrap, connect, rotation и
  reconnect.
- `Блокирует`: защищённый маршрут недоступен или состояние firewall нельзя доказать;
  трафик остановлен.
- `Снимается`: только после остановки tunnel/resources и проверки cleanup.
- `Требуется восстановление`: cleanup/lease verification не завершены; считать
  состояние `Отключено` запрещено.

### UX-требования

- Kill switch не предлагается отключить для исправления Tor, gateway, token,
  directory, UDP, QUIC или captive-portal ошибок.
- Явное отключение OnionRoute — отдельное пользовательское действие с проверенным
  shutdown, а не recovery shortcut.
- Если platform не может применить/проверить rules, OnionRoute не подключается.
- Split-tunnel exclusions описываются отдельно; нельзя называть их утечкой kill
  switch, если пользователь явно подтвердил исключение.

## Split tunneling

### Пользовательский текст

> Исключённые приложения работают вне OnionRoute. Они могут использовать реальный
> IP устройства, системный DNS, UDP и обычный маршрут Internet. Их трафик не
> защищён Tor или kill switch OnionRoute.

### Подтверждение исключения

**Заголовок:** Разрешить {application} работать вне OnionRoute?

> Сеть и сайты смогут видеть обычный IP и DNS этого приложения. Его соединения не
> будут заблокированы при сбое OnionRoute.

Кнопки: `Исключить приложение` и `Оставить защищённым`.

### Требования

- Default: все распознанные приложения protected; allowlist пуст.
- Неизвестная или неоднозначная application identity MUST блокироваться или идти в
  tunnel, но не исключаться автоматически.
- Список хранится локально в encrypted settings и не синхронизируется с account без
  отдельного privacy review.
- UI показывает постоянный счётчик приложений `Вне OnionRoute`.
- DNS split должен соответствовать route приложения; protected query не может уйти
  в system resolver.
- Platform limitations и приложения, которые нельзя надёжно классифицировать,
  публикуются поимённо в release notes.
